# Property Hub GH — SEO Audit & Recommendation Report

**Audit date:** 2026-08-12
**Repo:** property-hub-gh (Next.js 16 App Router, Tailwind v4, Supabase)
**Audit type:** Pre-launch code-based audit + launch-readiness plan (site not yet serving on production domain)
**Scope:** Technical SEO, on-page SEO, content/E-E-A-T, structured data, performance (CWV risks), AI search readiness, internal linking, sitemap/robots

> **⚠️ Critical context:** As of this audit, `https://propertyhubgh.com` serves a bare LiteSpeed server "Index of /" page and `https://www.propertyhubgh.com/robots.txt` returns 404. The Next.js app is **not deployed** and the database is empty (0 listings, 0 profiles). No SEO strategy can produce rankings until the app is deployed, DNS is pointed, HTTPS is live, and Search Console is verified. **Section A (HIGH #1) is the gateway to everything else in this report.**

## 2. HIGH — Fix at Launch (blocks indexing, wastes link equity, or risks trust)

### H1. Deploy the application — the domain is not live
- **Evidence:** `https://propertyhubgh.com` → LiteSpeed "Index of /"; `https://www.propertyhubgh.com/robots.txt` and `/sitemap.xml` → 404. No app route responds.
- **Impact:** Nothing is indexable. All metadata work is moot until deployment.
- **Fix (ordered):**
  1. Deploy to Vercel (recommended for Next.js 16) or a Node server supporting `next start` / standalone output.
  2. Point DNS: `www.propertyhubgh.com` + apex `propertyhubgh.com` to the host; enable HTTPS for both.
  3. Decide canonical host. Code already uses `https://www.propertyhubgh.com` everywhere (`layout.tsx:9`, `sitemap.ts:6`, `robots.ts:4`). If Vercel is used, add a redirect from the apex to `www` (or choose apex and update all hardcoded URLs — there are ~15 occurrences across `layout.tsx`, `sitemap.ts`, `robots.ts`, `page.tsx` OG blocks, `JsonLd.tsx`).
  4. Verify `robots.txt` + `sitemap.xml` return 200 on the chosen host.
- **Falsifiability:** `curl -I https://www.propertyhubgh.com` returns 200 with Next.js headers; `curl https://www.propertyhubgh.com/robots.txt` returns 200 and lists the sitemap.

### H2. Fix dead internal links (9+ routes that don't exist)
- **Evidence:**
  - `src/app/page.tsx:109` — "View All Properties" → `/search` (no route exists).
  - `src/app/page.tsx:217` — neighborhood cards → `/search?area=...` (no route exists).
  - `src/app/page.tsx:296` — "View Full Q3 Market Report" → `/insights` (no route exists).
  - `src/components/Footer.tsx:48-62` — `/about`, `/careers`, `/agents`, `/scout`, `/guides/buying`, `/guides/mortgage`, `/insights`, `/help` — none of these routes exist in `src/app/`.
- **Impact:** 404s on high-visibility links waste crawl budget, bleed link equity, and hurt E-E-A-T perception ("help center" and "buying guides" that don't exist).
- **Fix:** Either build the pages (guides/insights are genuinely useful SEO plays — see M10) or remove/point the links to real destinations (`/rentals`, `/sales`, `/safemove`). E.g., "View All Properties" → `/rentals`; neighborhood cards → `/rentals?neighborhood=East%20Legon`.
- **Falsifiability:** A crawl of the site reports zero internal links returning 404/soft-404.

### H3. Fix the sitemap
- **Evidence:** `src/app/sitemap.ts`
  - `:47-51` — queries all listings **without filtering** `status = 'active'` (or `moderation_status = 'approved'`). Pending/rejected listings will be submitted while the detail page renders them publicly anyway (see H6).
  - `:11, 60` — `lastModified: new Date()` on all static routes and floor for listings; Google ignores `lastmod` when it's always "now". The `listings` table *has* an `updated_at` column that is currently unused.
  - `:51` — `.limit(1000)` silently caps listings once the DB fills; there is no pagination or sitemap splitting.
- **Impact:** Soft-404s in the sitemap; lost freshness signal; capped coverage at 1,000 listings.
- **Fix:**
  - Add `.eq('status', 'active').eq('moderation_status', 'approved')` to the query.
  - Use `updated_at` for `lastModified`; use a real, stable date for static routes (content-change date, not `new Date()`).
  - Implement pagination/splitting when > 50,000 URLs (or just add `.lt('updated_at', cursor)` paging) and/or split static + dynamic into multiple sitemaps.
  - Drop `changeFrequency`/`priority` (Google ignores both — see L2).
  - Consider adding `/terms`, `/privacy`, `/cookie-policy`, `/copyright` — Google can't discover them otherwise (they're only linked from the footer on the homepage).
- **Falsifiability:** GSC sitemap report shows 0 "URL errors"; submitted URLs all resolve to 200 with `status=active` listings.

### H4. `/requests/[id]` pages: PII exposure + no metadata + no noindex
- **Evidence:** `src/app/requests/[id]/page.tsx`
  - No `generateMetadata` anywhere → every request page renders `<title>Property Hub GH</title>` (root default) and empty description.
  - `safeColumns` (`:51`) still exposes `seeker_name`, `location`, `budget`, `additional_details`, `purpose` to **anonymous** visitors.
  - Not disallowed in `robots.txt` (only `/requests` is allowed/indexed), no `robots: noindex` → detail pages are indexable with default titles.
- **Impact:** Thin, duplicate-title pages in the index; personal information (names, budgets, neighborhoods) publicly indexed; trust/E-E-A-T risk.
- **Fix (pick one, or both):**
  - Add `export const metadata = { robots: { index: false, follow: false } }` to `requests/[id]` — safest, and request detail pages carry no SEO value.
  - Or gate PII: require auth for `seeker_name`/`budget` on the detail view.
- **Falsifiability:** Google renders `/requests/[id]` with a `noindex` meta; `site:propertyhubgh.com/requests` shows only the listing page.

### H5. Remove fabricated homepage content (fake listings + fake counts)
- **Evidence:** `src/app/page.tsx`
  - `:22-59` — "featuredListings" (The Apex Residency, Vista Heights, Eco-Haven Estate) are **hardcoded demo props**, not live DB rows.
  - `:211-213` — neighborhood cards show fabricated counts ("124 listings", "87 listings", "63 listings") and link to a non-existent `/search?area=` route.
  - `:283-293` — "Rental Trend (GHS)" table ("+5.7% avg growth", Q3 market report link) is hardcoded marketing copy, not data.
- **Impact:** If publicly indexed, this is misleading-to-users content; Google's helpful-content systems devalue pages whose numbers are unverifiable; also breaks the "every space you see is verified" trust narrative (H1 tagline).
- **Fix:** After launch, render `featuredListings` from the DB (top by `views`/`is_verified`/`safemove_active`), and compute or remove the neighborhood counts and the market-insights table (or clearly label as editorial sample data). Remove the `/search` link (H2).
- **Falsifiability:** Homepage HTML contains only live listing titles; counts match `COUNT(*)` per neighborhood in the DB.

### H6. Enforce status filtering on listing detail pages (soft-404s for moderated listings)
- **Evidence:** `src/app/listings/[id]/page.tsx:206-210` fetches by `id` only — no `.eq('status','active')` / `moderation_status`. Sitemap (H3) compounds this by submitting all rows.
- **Impact:** Deactivated, rejected, or expired listings remain publicly indexable and render "Verified" styling inconsistent with moderation state; Google sees long-lived near-duplicate pages with no canonical harm but real UX/inventory issues.
- **Fix:** Query with `.eq('status','active').eq('moderation_status','approved')`; on miss, render the existing "Listing Not Found" state with a 404 status (ensure `notFound()` or manual 404 — the current branch returns 200).
- **Falsifiability:** A list of moderated-out listing IDs returns 404 when requested.

### H7. Make the SearchWidget functional (SearchAction schema makes a promise the UI doesn't keep)
- **Evidence:** `src/components/SearchWidget.tsx` — the search bar (`:49-54`) is an `<input>` + `<button>` with **no `<form>`, no submit handler, no navigation**. `src/components/seo/JsonLd.tsx:66-74` declares `WebSite.potentialAction.SearchAction` targeting `https://www.propertyhubgh.com/rentals?search={search_term_string}`.
- **Impact:** Google's sitelinks search box eligibility requires a working search URL; right now a user pressing Enter/Search does nothing — and the schema points at a query parameter the rentals page reads (`searchParams.search` is not handled — the rentals page reads `search` nowhere in its filters; the filter param is `neighborhood`, `region`, etc.). Google may drop the rich result and users bounce.
- **Fix:** Convert to a real `<form>` that navigates to `/rentals?search=...`; make the rentals page actually honor a `search` param (ilike on `title`, `neighborhood`, `description`) or remap the SearchAction template to a supported filter (e.g., `/rentals?region={search_term_string}`).
- **Falsifiability:** Submitting "East Legon" navigates to a filtered URL that returns matching listings; rich-results test shows the SearchAction resolving.

### H8. Add noindex on auth/account shell pages
- **Evidence:** `src/app/robots.ts:12-23` disallows `/admin`, `/dashboard`, `/login`, `/register`, `/post-space`, `/request-space`, `/unauthorized` — good. But none of these pages emit `robots: noindex`, so:
  - any external link, e-mail, or sitemap use can still get them crawled (robots.txt is a crawl block, not an index block — and Google may index robots-blocked URLs as "URL-blocked-by-robots" with titles shown).
  - `post-space`/`request-space`/`login`/`register` are `"use client"` CSR pages → near-empty HTML, high negative signal if indexed.
- **Impact:** Thin/blank pages in the index; duplicate titles.
- **Fix:** Add `export const metadata: Metadata = { robots: { index: false, follow: false } }` to `login`, `register`, `post-space`, `request-space`, `unauthorized`, and both `dashboard/layout.tsx` and `admin/layout.tsx` (layouts cover all children).
- **Falsifiability:** Direct fetch of `/login` with a Googlebot UA emits `<meta name="robots" content="noindex...">`.

### H9. Replace oversized hero/LCP images (Core Web Vitals)
- **Evidence:** `public/` file sizes:
  - `hero-bg.png` — **1,020 KB** (homepage LCP candidate, `page.tsx:67-73` renders it `priority` + `fill`)
  - `property-1.png` 940 KB, `property-2.png` **1,094 KB**, `property-3.png` 926 KB
  - `neighborhood-eastlegon.png` **1,181 KB**, `neighborhood-cantonments.png` 987 KB, `neighborhood-labone.png` 919 KB
- **Impact:** The LCP element's source is ~1MB PNG. Even with `next/image` auto-resizing, large viewport derivatives stay heavy → LCP > 2.5s risk on 3G/4G (majority of Ghanaian mobile users). CWV is a tiebreaker but a real one.
- **Fix:**
  - Re-export hero as WebP/AVIF below ~250-300 KB (hero is a generic estate photo — also request-permission to compress at the source).
  - Same for property/neighborhood cards (< 200 KB each); add explicit `sizes` attributes on `next/image` `fill` usages.
  - Move the Leaflet CSS (`layout.tsx:89-94`, unpkg) to be loaded only on pages that render a map (`PropertyVicinityMap`) — it's render-blocking CSS on every page including the homepage.
- **Falsifiability:** PSI/CrUX after deploy: LCP < 2.5s at p75 mobile; hero derivative ≤ 300 KB served.

## 3. MEDIUM — within 1 month of launch

### M1. Build programmatic location pages (single biggest ranking opportunity)
- **Evidence:** The marketplace already has the data model — `src/data/ghanaLocations.ts` (16 regions, ~67 neighborhoods), `src/data/propertyCategories.ts` (15 residential + 9 commercial categories), plus `config_regions`/`config_neighborhoods` in Supabase. Today the only indexable category pages are `/rentals` and `/sales`; every location filter is a `?query` URL that serves the same `Metadata` object and canonical.
- **Impact:** The Ghanaian SERPs for "apartments for rent in East Legon", "student hostels in Accra", "land for sale in Kasoa", "houses for sale Kumasi" are owned by Tonaton/Jiji/MeQasa — none have structured, fresh, verified listing pages per location. Property Hub GH can out-compete on freshness + verification E-E-A-T.
- **Fix:** Add indexable, pre-rendered template routes (e.g. `/rentals/east-legon`, `/rentals/ashanti`, `/sales/kumasi`, plus category+location like `/rentals/hostels/accra`) that:
  1. Generate unique `Metadata` per page (`generateMetadata` driven by slug → location) — title pattern: `Apartments for Rent in East Legon | Property Hub GH`.
  2. Serve the same filter component with location pre-selected.
  3. Include a 60%+ unique content block per page (neighborhood intro, price ranges from live `AVG(base_rent)` data, schools/amenities context, FAQ block) — follows the quality-gate rule: at 30+ location pages each needs substantial unique text; avoid pure filter shells.
  4. Self-referencing canonicals; add to sitemap (splits sitemap load from 1,000-listing cap).
  5. Useful for AI-search fan-out queries too ("what is the rent for a 2-bedroom apartment in East Legon 2026?").
- **Falsifiability:** Pages rank/are indexed for `site:` query; average session duration > 30s on location pages; CR per visit meets baseline within 60 days.

### M2. Improve listing page titles & descriptions
- **Evidence:** `src/app/listings/[id]/page.tsx:164-165`
  - Title = `"{Category} in {Neighborhood} | Property Hub GH"` — misses the transaction type and region; e.g. "Apartment in East Legon" could be "Apartment for Rent in East Legon, Greater Accra".
  - Description = `₵{price}. {first 150 chars of description}...` — starts with the cedi of `base_rent || outright_price` regardless of rent/sale, appends ellipsis even when short, and duplicate "(from `listing.description` substring)" — no "for rent/sale", no bedrooms/amenity hook.
- **Impact:** Weak CTR from SERP; keyword mismatch vs "for rent" queries.
- **Fix:** Compose title as `"{Category} for {Rent|Sale} in {Neighborhood}, {Region label} | Property Hub GH"` (respect ~60 char limit); description as a clean 140-155 char sentence using `base_rent` (rent, `/mo`) or `outright_price` (sale), bedrooms/bathrooms count, `is_verified`/SafeMove signal. Use `itemOfferedType` logic already present in schema (`JsonLd.tsx:132-137`).
- **Falsifiability:** Average SERP CTR for listing-URL impressions improves ≥ 0.5pp in GSC within 4 weeks.

### M3. Deepen listing-page content (E-E-A-T + AI extractability)
- **Evidence:** Listing page (803 lines) is heavy on chrome, light on text: description block only if `row.description` (`page.tsx` listing: `:438`), no seller entity block, no Q&A, no neighborhood context.
- **Impact:** YMYL-adjacent (money/tenancy); Google and AI engines (ChatGPT/Perplexity) prefer pages with complete entity data: who verified, what documents, what the area is like.
- **Fix:**
  - Require (or heavily encourage) description length ≥ 100 words at listing creation; render "About this {category}" boilerplate from category + location data when the poster left it blank.
  - Add a seller/agent card: `poster_role`, `company_name`, `is_verified_agent`, verified-at date (data already fetched: `:246-250`).
  - Embed a "Nearby" / neighborhood-context block (schools, markets, transport) and an FAQ section with 3-5 natural questions ("Is the rent advance 2 years? Is the land litigation-free?") — FAQPage schema for Google rich results was **retired** (2026-05-07); use plain visible Q&A content without FAQPage schema, or QAPage only for genuine user Q&A.
  - Keep `RealEstateListing` + `BreadcrumbList` JSON-LD (already present `:295-296`).
- **Falsifiability:** Median listing page text length > 300 words; AI-answer mention rate for long-tail listing queries increases (monthly manual check).

### M4. Robots.txt: complete AI-crawler coverage
- **Evidence:** `src/app/robots.ts:26-37` — named groups exist only for GPTBot, PerplexityBot, ClaudeBot. Per RFC 9309, named groups do **not** inherit the wildcard group's disallows.
- **Impact:** Missing explicit groups for `OAI-SearchBot` (ChatGPT search citations), `Google-Extended` (Gemini/AI tools), `anthropic-ai`, `Bingbot` (Copilot). Today they're allowed everywhere (fine) but unprotected if the wildcard list changes; conversely, the wildcard disallow of `/admin`, `/dashboard`, `/api` must be **repeated** in each named group — it already is, good.
- **Fix:** Mirror the wildcard disallows into `OAI-SearchBot`, `Google-Extended`, `anthropic-ai`, `Bingbot` groups; keep `allow: '/'`. Never block `/_next/` or `opengraph-image`. Decide deliberately whether CCBot (training crawler) is allowed — blocking CCBot doesn't block citations from ChatGPT/Perplexity (M4's key nuance).
- **Falsifiability:** `curl -A OAI-SearchBot` + robots.txt parse shows `/admin` disallowed and `/` allowed.

### M5. Verify canonical behavior for filter URLs
- **Evidence:** `/rentals`/`/sales` (`rentals/page.tsx:14-26`, `sales/page.tsx:14-26`) set static canonicals that collapse all query-param variants — that's actually *correct* practice. When M1 adds location pages, ensure the location pages carry their own canonicals and the `/rentals` dynamic page does **not** become a competing canonical for `/rentals/east-legon`.
- **Fix:** Confirm `alternates.canonical` on every new region/category page; add `robots: noindex,follow` only for meaningless combinations if they ever multiply (e.g., `?beds=1&beds=2` duplicates) — not needed yet.
- **Falsifiability:** GSC canonical report shows no cross-page canonical conflicts; each location page resolves to itself.

### M6. Reconcile social handles & Organization schema
- **Evidence:**
  - `src/components/seo/JsonLd.tsx:46-50` — `sameAs`: `twitter.com/propertyhubgh`, `facebook.com/propertyhubgh`, `instagram.com/propertyhubgh`.
  - `src/app/layout.tsx:57` — `twitter.creator: '@propertyhubgh'`.
  - `src/components/Footer.tsx:18-40` — real handles: `facebook.com/prophub.gh`, `instagram.com/propertyhub.gh`, `tiktok.com/@propertyhub.gh`, `x.com/propertyhub_gh`.
- **Impact:** Entity confusion; Google Knowledge Panel / recursive crawlers see mismatched profiles; `twitter.creator` points at a possibly-nonexistent account.
- **Fix:** Sync `sameAs` to the real handles (x.com/propertyhub_gh, facebook.com/prophub.gh, instagram.com/propertyhub.gh, tiktok.com/@propertyhub.gh); set `twitter.creator` to the actual X handle; consider adding `@id` consistency checks.
- **Falsifiability:** Schema validator shows 4 `sameAs` URLs returning 200 and matching the footer links.

### M7. Organization logo points at a photograph
- **Evidence:** `JsonLd.tsx:33-34` — `logo` and `image` both use `/hero-bg.png` (a 1MB photo), not a brand mark.
- **Impact:** Google uses `Organization.logo` for Knowledge Panel/branding; a photo fails the logo guidance and wastes a heavyweight asset.
- **Fix:** Add a real square logo (≤ 100-500 KB, transparent PNG/WebP or SVG) in `public/` and point `logo`/`image` at it.
- **Falsifiability:** `Organization.logo` URL returns an image ≥ 112px rendered as a logo.

### M8. `/requests` listing page: anonymize PII + fix `revalidate = 0`
- **Evidence:** `src/app/requests/page.tsx:12` — `export const revalidate = 0` forces a full server render on every hit; `:33` `safeColumns` still returns `seeker_name` to anonymous users (indexed content).
- **Impact:** Server cost (no caching) for a page in the sitemap with `daily`/`weekly` semantics; PII strings ("Kwame needs a 2-bedroom in East Legon, budget ₵2,500") become feed content.
- **Fix:** Replace `seeker_name` in the anonymous projection with "Seeker"/anonymized label; consider `revalidate = 60` or `"use cache"` with `cacheTag` + invalidation on new requests; keep noindex on details (H4).
- **Falsifiability:** Anonymous HTML contains no user names/phone numbers; page serves from cache flags after first render.

### M9. Route-level OG images for rentals/sales/location pages
- **Evidence:** `/rentals` and `/sales` OG reuse the root `opengraph-image` (rendered generic). `opengraph-image.tsx` exists only at root.
- **Impact:** Lower-quality social previews = lower CTR on WhatsApp/Facebook shares (the dominant sharing channel in Ghana).
- **Fix:** Add `rentals/opengraph-image.tsx`, `sales/opengraph-image.tsx` (and dynamic ones under listing routes if desired) using `ImageResponse` — small incremental work, meaningful share CTR.
- **Falsifiability:** `og:image` per route differs and renders the right category copy in ShareDebugger.

### M10. Build the promised content hub (guides + insights)
- **Evidence:** Footer already links `/guides/buying`, `/guides/mortgage`, `/insights` (Footer.tsx:59-62) — pages don't exist. Homepage "Market reports" section promises Q3 data.
- **Impact:** These are the highest-CR page types for real estate ("home buying in Ghana", "mortgage in Ghana", "rent vs buy Accra") and the strongest AI-citation magnets (comparison/definitive-guide formats get ~33%/15% of AI citations).
- **Fix (content plan, not just links):**
  1. `/guides/buying` — "How to Buy Land & Houses in Ghana Without Getting Scammed" (title checks, litigation-free land, conveyance, GREDA agents).
  2. `/guides/mortgage` — mortgage/rent-to-own landscape in Ghana.
  3. `/insights` — quarterly market data page (real, from listing aggregates — this legitimizes the homepage table).
  4. Each: author bylines, published/updated dates, citation of Ghana stats (Bank of Ghana, Land Commission), 1,500+ words.
- **Falsifiability:** Guides rank top-20 for their target queries within 3-6 months; guides drive ≥ 5% of organic sessions.

## 4. LOW — pointer to backlog

### L1. Remove the `keywords` meta tag
`layout.tsx:15-27` — Google ignores `keywords` entirely (no indexing/ranking effect); it's noise and a minor freshness liability since keyword lists go stale. Delete the array; keep `authors`/`creator` if desired.

### L2. Remove `changeFrequency` & `priority` from sitemap entries
`sitemap.ts` — Google ignores both; stripping them makes the file cleaner and removes the lie of `priority: 1.0` on the homepage.

### L3. Add `app/manifest.ts`
Not an SEO requirement — only needed if a PWA is planned. Skip otherwise.

### L4. Alt-text & image audit
Most images use `next/image` with alt (hero, neighborhood cards). Audit `ListingGallery`/`PropertyCard` for missing or file-name `alt`s (e.g., `alt={displayTitle}` in gallery — ensure descriptive). Low effort, marginal E-E-A-T signal.

### L5. Do NOT add FAQPage schema
FAQPage rich results were retired by Google on 2026-05-07 for all sites; no SERP benefit. Keep plain Q&A content (M3) for AI extractability; use QAPage only for real user-driven Q&A.

### L6. Wire `llms.txt`/`llms-full.txt` into the sitemap/robots and keep fresh
`public/llms.txt` + `llms-full.txt` exist and are good. Link them from the sitemap (`<lastmod>`-free `<url>` entries) so agents discover them; update as pages/features ship. Add agent-readable pricing/service copy as a `/pricing.md`-style file **after** monetization is decided (AI buyers value visible pricing — see H6/H7 interplay).

### L7. Honest `lastmod` everywhere
Covered under H3 — extends to any future blog: use real publish/update dates, never build-time `new Date()`.

### L8. Measurement stack (do at launch)
- Register GSC + submit sitemap; verify both `www` and apex, set preferred domain.
- GA4 + Bing Webmaster Tools + IndexNow.
- Monthly AI-visibility check: top 20 queries in ChatGPT/Perplexity/Google AI Overviews; log which pages get cited.
- Optional: Otterly/Peec/ZipTie for share-of-AI-voice tracking (covered by L8/A2 in appendix).
